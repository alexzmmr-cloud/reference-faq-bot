## 1.1 Целевой сценарий

Пользователь должен пройти основной маршрут:

1. Отправляет `/start`
2. Видит приветствие и 4 inline-кнопки
3. Нажимает FAQ-кнопку (`callback_data = faq:<id>`) → получает ответ из `faq.json` + кнопки снова
4. Пишет свободный текст с ключевым словом → получает подходящий ответ + кнопки снова
5. Пишет нераспознанный текст → получает вежливое «не понял» + предложение кнопок/оператора
6. Нажимает «Связаться с оператором» → бот просит одно сообщение
7. Присылает текст → бот сохраняет в `requests.sqlite3` (`operator_requests`) и подтверждает приём
8. (Граничный случай) Присылает не текст во флоу оператора → бот просит именно текст, запись не создаётся

## 1.1 Целевой сценарий

Пользователь проходит флоу оператора как в v1 (см. цикл 1.0), с добавлением:

1. Пользователь присылает текстовое обращение во флоу оператора
2. Бот сохраняет обращение в `operator_requests` (как в v1)
3. Бот пытается отправить уведомление на каждый уникальный chat_id из `OWNER_CHAT_ID`/`ADMIN_CHAT_ID` с текстом обращения, `telegram_user_id` и `username`
4. Пользователь получает подтверждение «обращение принято» независимо от результата отправки уведомления
5. (Граничный случай) Отправка уведомления не удалась — ошибка логируется, пользователь всё равно получает подтверждение
6. (Граничный случай) Ни `OWNER_CHAT_ID`, ни `ADMIN_CHAT_ID` не заданы/невалидны — бот не стартует, кидает понятный `RuntimeError` при запуске

## 1.2 Что не входит в текущую версию

- Разные chat_id для owner и admin (используется один и тот же id для обеих переменных)
- Повторные попытки (retry) при сбое отправки уведомления
- Уведомления по другим событиям, кроме нового обращения к оператору
- Разметка/форматирование уведомления (HTML/Markdown) — обычный текст

## 1.3 Допущения и открытые вопросы

### Допущения

- В тестовом режиме `OWNER_CHAT_ID` и `ADMIN_CHAT_ID` содержат один и тот же chat_id пользователя
- Уведомление отправляется синхронно, сразу после успешной записи в БД, до ответа пользователю (но не блокирует сам ответ при сбое)

### Вопросы, которые нельзя восстановить из входа
