# AGENTS.md — reference_faq_bot

Правила для агента, работающего в этой директории.

## Обязательное чтение перед работой
- Перед любым шагом читать `spec.md` и `Plan.md` в этой же директории — это источник правды по функционалу, форме данных и границам.
- Работать по одному шагу `Plan.md` за раз, не забегать вперёд и не пропускать шаги.

## Секреты
- Никогда не печатать, не запрашивать и не вставлять настоящий `BOT_TOKEN`, `OWNER_CHAT_ID`, `ADMIN_CHAT_ID` в чат/ответы ассистента.
- `.env` не коммитится и не публикуется. `.env.example` содержит только заглушки.
- Токен и chat_id не должны появляться в логах, коде, README или коммитах.

## Границы reference-flow (не добавлять без отдельной задачи)
- Разные chat_id для owner и admin (v2 использует один и тот же chat_id для обеих переменных) и retry при сбое отправки уведомления
- VPS, деплой на сервер, production-эксплуатация
- Webhook (используется только long polling)
- API ИИ / LLM-интеграции
- CRM-интеграции
- Приём оплаты
- Web-админка или любой frontend
- Многоязычность
- Автотесты сверх smoke-check в Telegram (описанного в `Plan.md`)

## Форма данных
- `faq.json` и схема таблицы `operator_requests` — зафиксированы в `spec.md`. Менять их нельзя без обновления `spec.md`.
- Новые FAQ-разделы или поля сверх зафиксированного списка не добавлять без отдельной задачи.

## Работа с Plan.md
- После каждого шага — отметка чекбокса и запись фактического исхода в поле «Итог» (контрольная точка при успехе / ошибка при провале).
- Не пересобирать план целиком без причины — править точечно.
