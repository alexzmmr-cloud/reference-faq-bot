# Reference FAQ Bot

Учебный Telegram-бот на aiogram для FAQ онлайн-школы: отвечает на вопросы по кнопкам и по ключевым словам, принимает обращения к оператору и уведомляет о них владельца/админа.

## Файлы проекта

- `bot.py` — точка входа: обработчики `/start`, FAQ-кнопок, текстового поиска, флоу оператора, уведомления владельцу, запуск long polling
- `db.py` — работа с SQLite: создание таблицы `operator_requests`, сохранение обращений
- `faq_service.py` — загрузка `faq.json`, поиск раздела по `id` и по ключевым словам
- `faq.json` — данные FAQ (разделы `about`, `price`, `format`)
- `requirements.txt` — зависимости с зафиксированными версиями
- `.env.example` — шаблон конфигурации (заглушки токена и chat_id)
- `.env` — локальный файл с настоящими `BOT_TOKEN`, `OWNER_CHAT_ID`, `ADMIN_CHAT_ID`, не коммитится
- `requests.sqlite3` — локальная база с обращениями к оператору, создаётся автоматически при первом запуске, не коммитится
- `spec.md` — контракт по данным и границам функционала
- `Plan.md` (`plan.md`) — пошаговый план реализации с отметками о выполнении
- `AGENTS.md` — правила и ограничения для агента, работающего в этой директории

## Зависимости

- Python 3.13
- `aiogram==3.28.2`
- `python-dotenv==1.2.2`

## Установка

```bash
cd reference_faq_bot
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## Настройка токена и уведомлений

1. Создать учебного бота через [@BotFather](https://t.me/BotFather) командой `/newbot`
2. Скопировать `.env.example` в `.env` (или отредактировать существующий `.env`)
3. Вставить полученный токен в `.env`:
   ```
   BOT_TOKEN=<токен из BotFather>
   ```
4. Узнать свой Telegram chat_id (например, через [@userinfobot](https://t.me/userinfobot)) и указать его в `.env` для получения уведомлений о новых обращениях к оператору:
   ```
   OWNER_CHAT_ID=<ваш chat_id>
   ADMIN_CHAT_ID=<ваш chat_id>
   ```
   В текущей версии обе переменные указывают на один и тот же chat_id (роли не разделены); достаточно заполнить хотя бы одну из них.
5. Чтобы бот мог написать вам первым, до запуска нужно один раз отправить `/start` вашему боту в Telegram — иначе Telegram не разрешит боту инициировать переписку.
6. `.env` никогда не коммитится и не публикуется — исключён через `.gitignore`

## Запуск

```bash
source .venv/bin/activate
python3 bot.py
```

Бот стартует через long polling. При старте создаётся файл `requests.sqlite3` с таблицей `operator_requests`, если его ещё нет.

Если `BOT_TOKEN` или chat_id не заданы (остались заглушки), бот не стартует и выводит понятную ошибку конфигурации.

## Что проверено (smoke-check)

В Telegram вручную пройден полный сценарий:

- `/start` — приветствие и 4 inline-кнопки
- Каждая FAQ-кнопка («О курсе», «Стоимость», «Формат обучения») — ответ из `faq.json`, кнопки показываются повторно
- Свободный текст с ключевым словом — находит соответствующий FAQ-ответ
- Нераспознанный текст — вежливое «не понял» с предложением выбрать кнопку или оператора
- «Связаться с оператором» + текстовое сообщение — обращение сохраняется в `operator_requests`, владелец/админ получает уведомление, пользователь получает подтверждение
- «Связаться с оператором» + нетекстовое сообщение (стикер/фото) — бот просит прислать текст, запись не создаётся

Результат подтверждён SQL-запросом к `requests.sqlite3` — сохранённая запись содержит все 5 полей (`id`, `telegram_user_id`, `username`, `message_text`, `created_at`). Уведомление владельцу/админу подтверждено вживую в Telegram: приходит отдельным сообщением с текстом обращения, `user_id` и `username`, до подтверждения пользователю.

Если отправка уведомления не удалась (невалидный chat_id, владелец не запускал бота), это не блокирует ответ пользователю — ошибка только логируется. Бот не запустится, если ни `OWNER_CHAT_ID`, ни `ADMIN_CHAT_ID` не заданы или невалидны.

## Ограничения текущей версии

- Только Telegram-бот, без веб-интерфейса
- Нет реальной пересылки обращений оператору вручную — только сохранение в SQLite и уведомление владельца/админа
- Owner и admin не разделены — используется один и тот же chat_id для обеих переменных, без ретраев при сбое отправки
- Нет редактирования `faq.json` через бота, многоязычности, VPS/деплоя, вебхуков, API ИИ, CRM, оплаты
- Нет автотестов — проверка только через ручной smoke-check в Telegram

Полный контракт по данным и границам — в [`spec.md`](spec.md).
